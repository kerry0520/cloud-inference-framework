- 单 rank、两页：写入并确认 a/b 后，c 分配得到 -1；a/b 继续命中，a 可以复用。另一个控制组显式释放失败写的页后，新 key 能使用该页。
- 单 rank、剩一页但请求两页：两个 key 都得到 -1，一页仍空闲。这是批次全有或全无行为，是否应该改为部分分配需要确认调用者约定，不能直接称实现错误。

**不能直接加一个简单 LRU 就声称修好。** 当前 `get_key_locations` 返回裸页位置，调用者随后异步读取；`is_complete` 只表示各 rank 写入已确认，不表示没有读取者。淘汰后立即覆写同页可能让已拿到位置的读者读到新内容。下一步应先追 connector/worker 读写、确认、失败清理和 rank 对齐，明确读租约／引用或版本验证等机制；若范围超出小 PR，先请求拆分，不能用全局锁冒充跨进程 IO 保护。也不能未经确认把部分分配作为安全的小子任务抢做。
