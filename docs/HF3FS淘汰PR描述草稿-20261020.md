## 标题

```
[Core][KV Connector] Evict HF3FS pages under reader leases
```

## 正文

```markdown
## Purpose

A full HF3FS page pool permanently fails every save: the metadata server has no
way to return pages once `allocate_pages_for_keys` runs out (issue #62389).
#62393 stops cache hits and duplicate keys from consuming *new* pages, but it
deliberately does not add eviction, so the failure remains.

This PR adds eviction. Naively evicting the least-recently-used key is unsafe:
the scheduler calls `batch_key_exists` before the worker loads the block, so a
key can be "a hit" while its page is still about to be read. Recycling that page
would turn a hit into a load failure or into another request's data.

## What this does

- **Reader leases.** `POST /keys/acquire` returns page locations *and* pins the
  keys; `POST /keys/release` drops the pin. The load path
  (`AsyncOperationManager._handle_load_task`) acquires before reading and
  releases as soon as the blocks are in host buffers, on success, on a missing
  key, on read failure, and on exceptions.
- **LRU eviction of safe keys only.** When allocation needs more pages than the
  free list has, the server reclaims complete, unleased keys that are not part of
  the allocating request (`exclude=cached_pages`), oldest first, returning one
  page per rank to the free list and deleting the key.
- **Lease expiry.** Leases carry a monotonic deadline (default 120 s,
  `--lease-ttl-s`) so a crashed client cannot pin pages forever. The TTL must
  exceed the slowest block load — it is a safety parameter, not a tuning knob.
- **Backward compatible.** `Hf3fsMetadataInterface.acquire_keys/release_keys`
  have non-abstract defaults (plain lookup / no-op), so the mock and single-node
  clients are unaffected; the HTTP client falls back to `get_key_locations` on
  404/405, which is safe against an older server because it never evicts.

## Correctness argument

- A page is only handed out after it is in the free list; eviction releases it
  there first.
- Only complete keys are tracked for eviction; partial keys remain owned by their
  writer (the boundary with #61247).
- A key with a live lease is never evicted; lease owners release or expire.
- Eviction cannot target the allocating request's own hits, so a batch that
  already decided to read a page cannot recycle it underneath itself.

## Testing

- `tests/v1/kv_connector/unit/test_hf3fs_metadata_server.py` gains 7 cases:
  eviction makes room, leases protect, expired leases are reclaimed, partial keys
  are skipped, same-request hits are not evicted, LRU order respects acquires,
  and eviction returns one page per rank.
- Isolated harness (full source + upstream tests, only the import path rewritten,
  `--noconftest`): **25 passed**, plus a real localhost HTTP probe that leases
  every complete key, asserts allocation fails, releases one, and asserts the
  eviction landed on that key.

## Not verified here

- Two vLLM instances sharing one metadata server on real 3FS (someone with a 3FS
  setup needs to run it; @sivabreddy offered).
- The writer-side boundary with #61247.
- Eviction cost / hit-rate impact: this PR is about correctness, not policy.
- Connector-level unit tests were not run on the authoring machine (no GPU/torch
  in the review environment); the connector change is small and reviewed by hand.
```

## 审阅时要特别看的三处

1. `evict_lru` 里 `num_pages` 的单位：每个被淘汰的 key 在**请求方 rank** 上只还一页，
   所以“需要几页”就等于“淘汰几个 key”；若将来改成按 rank 各自计数，这里要跟着改。
2. `release_leases()` 先清标志再发 RPC：若反过来，RPC 失败后重试会把别人刚加的租约减掉。
3. 过期租约的语义：`lease_expiry > now` 才算“活着的读者”，等于说 TTL 到期即假定读者已死。
   这个假设必须写进文档，否则真实 3FS 上慢读会被误判。
