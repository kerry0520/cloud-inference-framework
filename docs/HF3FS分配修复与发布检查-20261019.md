## 范围更正

**本轮只完成同一问题中的分配容量子问题，不声称完整修复 #62389。** 最初候选包含在线淘汰，但源码确认不仅后台读取需要保护，scheduler 的 `batch_key_exists` 在 worker 真正加载前已用于计算外部命中。只在 `get_key_locations` 之后加锁仍有窗口：scheduler 决定命中→淘汰覆写→worker 加载失败/错误数据。现有 worker 失败完成也不能自动视为 scheduler 已重新计算。安全 LRU 必须跟踪调度命中、读完成、写入所有权、终止／取消、多 rank 与混合版本；不能作为简单小补丁宣称完成。本轮未实现或启用淘汰。

可以独立提交的真实 bug 是：完整缓存命中也计入新页预算，导致剩余空间足够服务新 key 时错误失败。另一个同路径问题是重复新 key 消耗多页但字典响应只保留最后一页。本轮改为先识别完整命中，再对不同的新 key 一次分配；miss 批次不足仍全部失败，不变更协议或回收已有页。
