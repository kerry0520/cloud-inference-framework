# min-p 候选设计与验收

本轮副目标候选：固定 vLLM 0.31.0 的 MRV2 采样路径 `SamplingStates.apply_min_p`。只有请求启用非零 min_p 时调用，之前的 greedy 基线不能用于宣称该优化收益。

职责与契约：按 request mapping 找到每行 min_p，原地保留大于等于 `row_max + log(min_p)` 的 logits，其余置为负无穷；min_p=0 的行不变。与数学上的概率阈值等价，避免额外 softmax。输入为行内连续的 logits、请求映射及 min_p 表，允许行步长大于词表宽度。

原实现每行一个线程块，以1024元素为块串行遍历词表两次。候选先以4096元素为块并行计算部分最大值，再由多个块归约少量最大值并并行过滤。代价是额外启动一次内核和一个小临时缓冲区；小词表或高 batch 未必获益。当前公开 main 同路径仍为原结构，但仅是文件核查，没有认领 issue 或排除所有在途 PR。

需保护的失败：尾部越界、索引映射错误、min_p=0 行被修改、阈值不等号变化、无穷/NaN语义变化、行 padding 被覆盖、真实路径未接入。最低成本先用真实上游函数与候选做逐字节对照，再用引擎实际 logits 验证；无需一开始下载更多模型。

局部验证覆盖多种词表边界、batch、dtype、非平凡映射、混合 min_p、非连续行与特殊值。计时使用相同形状和请求配置的上游函数，采用 Triton do_bench 的 L2清理与 CUDA events，并保存 ABBA 重复结果；不把合成计时当端到端收益。

引擎层通过公开 worker extension 与字符串 RPC 安装候选，不开启不安全序列化。验证模式保留真实调用输入及原版/候选完整输出；性能模式移除逐值比较与拷回，只保留两臂一致的调用计数。正式框架源码尚未修改，当前为本地受控接入候选，不代表上游已接受。
