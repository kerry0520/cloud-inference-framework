## 本机结果入口

- `results/minp-sweep-20261018T051134Z`：FP16、V151936下两行版batch1/2/4/8约4.18/3.57/3.55/3.67×；V32000和batch32/64/256也有观测。其计时采用排队多次调用、每轮均值后取最小，非独立冷启动延迟。
- `results/abba-knob-20261018T051230Z`：24轮ABBA/BAAB；batch1/2/4/8请求平均decode间隔变化约−0.77/−0.80/−0.78/−0.80%；batch2的wall区间跨0。
- `results/minp-compare-20261018T052250Z`（FP16）、`minp-compare-f32-20261018T052310Z`（FP32）：本机upstream／knob／#58907三方对照，两行版在该矩阵最快。真实引擎logits是FP32，第二设备优先跑该dtype。
- `results/upstream-pr-58907.diff`：当时抓取的PR快照，不能代替在线最新diff。

`do_bench_cudagraph`在当前Triton中把多次调用展开到一张图里重放并除以次数，输出是摊销每调用时间，不是“单个内核一次启动”的隔离延迟。它与排队协议均有数据复用和缓存语境，不能与清L2微基准或引擎时间直接混算。

旧实验 `minp-sweep-050921Z/050946Z/051019Z/051034Z/051059Z` 和 `minp-compare-052232Z` 曾被删除，无法恢复其完整原件。前者计时协议有误，后者闭包捕获导致变体相同；均不作结论证据。此后严格遵守保留失败规则。
