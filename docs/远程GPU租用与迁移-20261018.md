## 准备顺序

在远端clone本项目public仓库后，固定到**本轮修复提交**（SHA见当前交接与Git；本地提交未推送时远端clone不会包含它，需先迁移该提交）。既有仓库先检查状态，不盲目pull覆盖。

```bash
cd /root/ci-fw
export CI_RUNTIME_DIR=/opt/cloud-inference-framework
export CI_DATA_ROOT=/root/autodl-tmp
bash scripts/remote_bootstrap.sh --facts-only
bash scripts/repro_l4.sh --dry-run
bash scripts/remote_bootstrap.sh
```

bootstrap会安装固定核心依赖和匹配CUDA编译组件，记录完整解析清单及真实CUDA检查；检查上游源码HEAD和工作区；按本仓库固定HF元数据下载并校验全部必要文件。下载使用venv Python标准库，不再猜测第三方CLI名称或跨平台revision含义。`HF_ENDPOINT`可设置为可访问镜像，文件仍按固定HF blob/LFS哈希验证。部分下载留下.partial，缺文件重跑可补齐；校验失败停止并保留坏文件，不能当作已完成。

`CI_RUNTIME_DIR`是运行时根；`CI_DATA_ROOT`把大型目录链接到数据盘。pip缓存默认也可能占系统盘，安装前检查空间，必要时设置 `PIP_CACHE_DIR=/root/autodl-tmp/pip-cache`。源码已有改动或版本不同则停止，不自动reset。编译适配支持WSL和Linux driver库发现，最终以preflight为准。

preflight验证真实GPU矩阵运算、pinned-memory复制和FlashInfer采样，**不是完整LLM forward验收**。模型引擎首次执行由后续最小真实请求验收。

## 按预算逐步执行

先跑真实logits dtype的内核对照，再端到端，剩余预算才做更长项目：

```bash
STAGES="minp-compare-f32" bash scripts/repro_l4.sh --dry-run
STAGES="minp-compare-f32" bash scripts/repro_l4.sh
bash scripts/run_stage.sh abba-knob --rounds 1 --batches 1 --prompt-len 32 --max-tokens 4
STAGES="abba-knob" bash scripts/repro_l4.sh
# 通过且预算允许后，选择追加阶段或完整矩阵：
bash scripts/repro_l4.sh --dry-run
bash scripts/repro_l4.sh
```

正式长配对运行前应先做短请求确认引擎能加载；完整矩阵含FP16/FP32对照，首个stage失败即停，保留证据。dry-run只打印计划，不验证依赖或安装成功。默认估时只是本机参考，不保证远端耗时。单次最多3小时仅为上限，实际仍受用户明确预算约束；发现费用、环境或连续失败问题先停下报告。

每轮目录有随机后缀，避免同秒覆盖。结果目录、日志和真实退出码都要保留。远端运行与本机GPU实验不交错抢占同一设备。脚本没有真实租用机全流程验收，不能把本地冒烟写成远端已通过。
