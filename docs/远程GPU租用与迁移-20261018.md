# 租一台 GPU 复现：平台选择与交接方式

状态（2026-10-18）：**未租、未花钱**。本文只回答三件事：去哪儿租、我怎么远程操作、
代码和数据怎么搬。真正开跑前仍需要你给平台、预算上限和付款方式（AGENTS.md 的付费授权）。

## 1. 选哪个平台

先明确需求：只需要一张 **≥24 GB、驱动够新** 的卡，跑 1–2 小时，证明"结构性结论换机器仍成立"，
不需要多卡、不需要高速互联。Qwen3-0.6B 在 8 GB 卡上都能跑，24 GB 只是为了 batch 8 和 8k 上下文不 OOM。

| 平台 | 付款 | 上手 | 驱动 / CUDA | 适合本项目的点 | 风险 |
| --- | --- | --- | --- | --- | --- |
| **AutoDL** | 人民币，支付宝/微信 | 最省事，镜像预装 conda/torch，社区教程多 | 镜像多为 CUDA 11.8–12.4，**驱动常低于 580** | 便宜、按小时、有 `/root/autodl-tmp` 数据盘、有 `source /etc/network_turbo` | 我们的 vLLM 0.31.0 轮子按 CUDA 13 编译，老驱动可能加载失败 |
| 阿里云 / 腾讯云 按量 GPU | 人民币，需实名与余额 | 中等，要自己选镜像装环境 | 可自选新驱动镜像（580+），可控 | 网络稳、可开 4090/A10/L20、按量计费 | 单价高（同卡约为 AutoDL 的 2–3 倍） |
| **RunPod** | 美元，信用卡 | 中等，社区镜像多 | 驱动较新，L4/A10 上手即用 | L4 24 GB 便宜、按秒计费、SSH 直接给 | 需国际信用卡；国内网络访问慢 |
| Lambda / Vast.ai | 美元 | 中等 | 较新 | 便宜、卡型多 | 需信用卡、实例被抢风险 |

**建议顺序**

1. **AutoDL 先试**：租一张 4090 或 L20（24 GB），开机后第一件事 `nvidia-smi` 看驱动。
   - 驱动 ≥ 580 → 全量 `repro_l4.sh`（含 vLLM 的端到端配对）。
   - 驱动 < 580 → 用 `--torch-only` 只跑三个 torch/Triton 阶段（fp8 单算子、min-p 扫参、三方对比）。
     这三个恰好是"内核级结论换硬件"最需要的部分，仍然有说服力。
   - 想省钱可用**无卡模式**开机做 `remote_bootstrap.sh` 的安装（约 ¥0.1/小时），装完再切到 GPU 模式跑实验。
2. 若一定要跑全量端到端、又不想折腾驱动 → **RunPod 的 L4**（约 $0.4–0.6/小时）或阿里云选新驱动镜像。
3. 不建议为了这件事办 GPU 平台的年卡/包月。

费用量级：环境 15–25 分钟 + 实验约 63 分钟 + 来回传数据 5 分钟 ≈ **1.5–2 小时**；
AutoDL 4090 约 ¥2/小时、L20 约 ¥2.5–3/小时 → **¥4–6**；RunPod L4 约 **$1–1.5**。
具体价格以控制台为准，我不替你下单。

## 2. 怎么让我远程干活

我这边通过 WSL 里的 `ssh` 客户端非交互地操作远程机器（WSL 已装 OpenSSH 9.6 与 rsync 3.2.7）。
需要你做的只有三步：

1. **租实例**，在控制台找到登录命令，形如
   `ssh -p 23456 root@region-12.autodl.com`（端口和域名每个实例不同）。
2. **把我的公钥贴进去**。在实例的 JupyterLab 终端 / 网页终端里执行（把整行换成下面的公钥）：

   ```bash
   mkdir -p ~/.ssh && chmod 700 ~/.ssh
   echo 'ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAINcirPYa+Iu3HaMulMSf0YTU7oSk8nDZbFUdWytXdbyh ci-fw-autodl' >> ~/.ssh/authorized_keys
   chmod 600 ~/.ssh/authorized_keys
   ```

3. **把 `host`、`port` 发我**（例如 `region-12.autodl.com 23456`）。**不要发密码**，
   密码对我没用，也不该出现在聊天记录里。

之后我会：

```bash
# 1. 先验通路和环境，不装任何东西
ssh -p <port> -i ~/.ssh/id_ed25519_autodl root@<host> \
  'nvidia-smi; python3 --version; df -h /root'

# 2. 拉仓库（public，无需 token）并按需装环境
ssh ... 'git clone https://github.com/kerry0520/cloud-inference-framework /root/ci-fw'
ssh ... 'cd /root/ci-fw && CI_DATA_ROOT=/root/autodl-tmp bash scripts/remote_bootstrap.sh --facts-only'
ssh ... 'cd /root/ci-fw && CI_DATA_ROOT=/root/autodl-tmp bash scripts/remote_bootstrap.sh'
```

`remote_bootstrap.sh` 会：建 `CI_RUNTIME_DIR`（默认 `/opt/cloud-inference-framework`，
可用 `CI_DATA_ROOT` 把 `.venv`/`models`/`vllm-src` 链接到数据盘）、装 vLLM 0.31.0、
拉 Qwen3-0.6B 固定 revision、拉 vLLM 固定 commit `db9527a`、跑一次 `preflight.sh`，
并把结果写进 `results/bootstrap-remote-<utc>/`（`facts.txt`、`versions.txt`、`report.env`、日志）。

然后照旧一条命令跑实验（失败 stage 保留目录、继续后面的）：

```bash
ssh ... 'cd /root/ci-fw && CI_RUNTIME_DIR=/opt/cloud-inference-framework \
  bash scripts/repro_l4.sh --dry-run'
ssh ... 'cd /root/ci-fw && CI_RUNTIME_DIR=/opt/cloud-inference-framework \
  bash scripts/repro_l4.sh'
```

最后我把结果拉回本仓库、写进文档、提交并推送：

```bash
rsync -az -e "ssh -p <port> -i ~/.ssh/id_ed25519_autodl" \
  root@<host>:/opt/cloud-inference-framework/results/ \
  "C:/Users/32065/Documents/ChatGPT/云端推理框架/results/remote-<平台>-<日期>/"
```

## 4. 安全与费用边界

- 用**专用密钥** `~/.ssh/id_ed25519_autodl`（本轮新生成，指纹 `SHA256:vobtq2751u7DQTKJk9iUt3JlltnoiHERQhU/0Kqtfcg`），
  只用于这类一次性实例；用完你把 `~/.ssh/authorized_keys` 里那行删掉即可吊销。
- 我不会把密码、token、私钥写进仓库、文档或命令历史；仓库会公开，所以这些永不入库。
- 我只跑 `repro_l4.sh` 里的 stage，不装别的服务、不开公网端口、不跑训练。
- 时间盒：单次租用 ≤ 3 小时；超过预算或 stage 反复失败我就停下报告，不自行续费。
- 结束后：先 `rsync` 回结果，再让你关机/销毁；我不会代为关闭你的账号或实例。

## 5. 失败预案

| 现象 | 处理 |
| --- | --- |
| `torch` 报 `driver too old` / CUDA 初始化失败 | 用 `--torch-only` 重跑 bootstrap，只跑 `quant-probe`/`minp-sweep`/`minp-compare` |
| `git clone` 卡住 | AutoDL：`source /etc/network_turbo` 后重试；或把仓库打成 zip 用 `scp` 传 |
| ModelScope 下载慢 | 脚本自动回退 `HF_ENDPOINT=https://hf-mirror.com` |
| 系统盘满（pip 缓存） | `CI_DATA_ROOT=/root/autodl-tmp` 让 venv 落数据盘；必要时 `pip cache purge` |
| 实例被抢占/关机 | 重新开同一实例（数据盘保留），重跑 bootstrap（幂等）后继续 |

## 6. 这一步能证明什么、不能证明什么

能证明：权重流模型的比例关系（`lm_head` 约占单步 20%、层内 GEMM 时间 ∝ 字节）、
min-p 局部加速与端到端 1% 量级、fp8 干预带来的 ~26%（而非 40%）——**在不同卡上方向一致**。

不能证明：绝对吞吐可外推到生产；单请求延迟可代表线上；多卡/张量并行下的行为。
这些会写进结论限制，不会因为换了张卡就消失。

## 8. 接机清单（收到 host/port 后的前 10 分钟）

2026-10-18 状态：用户确认 AutoDL 上有驱动 >580 的机器，但当晚全部满租，**等有空机再开**。
下列步骤是那一天的固定顺序，换 agent 接手也照此执行；任何一步失败都保留日志、不猜。

```bash
KEY=~/.ssh/id_ed25519_autodl
H=<host>; P=<port>

# 1. 通路与事实（不装东西，30 秒）
ssh -o BatchMode=yes -o ConnectTimeout=10 -p "$P" -i "$KEY" root@"$H" \
  'nvidia-smi --query-gpu=name,driver_version,memory.total --format=csv,noheader;
   python3 --version; df -h /root /root/autodl-tmp 2>/dev/null | tail -3'

# 2. 拉仓库并收集事实
ssh -p "$P" -i "$KEY" root@"$H" \
  'git clone -q https://github.com/kerry0520/cloud-inference-framework /root/ci-fw &&
   cd /root/ci-fw &&
   CI_DATA_ROOT=/root/autodl-tmp CI_RUNTIME_DIR=/opt/cloud-inference-framework \
     bash scripts/remote_bootstrap.sh --facts-only'

# 3. 判断：驱动 >=580 走全量，否则 --torch-only
ssh -p "$P" -i "$KEY" root@"$H" \
  'cd /root/ci-fw && CI_DATA_ROOT=/root/autodl-tmp \
     bash scripts/remote_bootstrap.sh'          # 或 ... --torch-only

# 4. 先看计划，再跑
ssh -p "$P" -i "$KEY" root@"$H" \
  'cd /root/ci-fw && bash scripts/repro_l4.sh --dry-run'
ssh -p "$P" -i "$KEY" root@"$H" \
  'cd /root/ci-fw && bash scripts/repro_l4.sh'

# 5. 拉回结果（本机执行）
rsync -az -e "ssh -p $P -i $KEY" root@"$H":/opt/cloud-inference-framework/results/ \
  "C:/Users/32065/Documents/ChatGPT/云端推理框架/results/remote-autodl-$(date -u +%Y%m%dT%H%M%SZ)/"
```

判定规则：驱动 <580 且 vLLM 装不上 → 只跑 `quant-probe`/`minp-sweep`/`minp-compare`，
在文档里写明"租用机只验证了内核级结论"；驱动 ≥580 但显存 <24 GB → 去掉 `quant-context` 的 8192。
时间盒：单次租用不超过 3 小时，超过或连续两个 stage 失败就停下报告。
