# 第六阶段：FP8 配置干预与上下文扫描（2026-10-18，复核修订）

范围：vLLM 0.31.0、Qwen3-0.6B、RTX 5060 Laptop 8GB、未锁频。原始结果不改写；本次修订纠正预测、跨臂相减和因果表述。FP8 是框架已有配置，不是本项目自研量化。

## 方法与预测修订

同一进程依次启动 FP16／在线 FP8 W8A8 引擎，交替臂顺序；greedy、合成 prompt 128、输出64，启动与预热不计正式间隔。这里的 decode_ms 是每个请求 first/last token 时间差除以间隔数，再汇总中位数，**不是逐 token ITL 的 P50/P99**。

历史约 −40% 的预测撤回：第三阶段 83.8% 是全部 GEMM，含 lm_head 的20.4%；层内四类 GEMM约63.4%。若只让层内时间减半、其余不变，条件估计为内核累计时间下降31.7%，不能直接当未插桩请求间隔的预测。原始 config/summary 中的旧预测保留以便追溯。

W8A8 同时改变权重与激活精度、执行内核、融合和量化开销，不是只改变权重字节的单变量实验。实测不量化 lm_head。

## 主要结果

| batch | FP16 请求平均 decode 间隔中位 ms | FP8 ms | 轮级配对变化 |
|---|---:|---:|---:|
| 1 | 4.2348 | 3.0587 | −25.94% |
| 2 | 4.5187 | 3.3633 | −26.75% |
| 4 | 4.5971 | 3.5400 | −24.24% |

第二个独立会话 `quant-decode-20261018T091928Z` 对应 −25.71%／−26.56%／−24.99%。两次结果方向与量级相近，仍不是跨设备结论；轮数少，不把小样本 bootstrap 当广泛稳定性保证。

`quant-probe-20261018T090015Z`／`090044Z`：torch._scaled_mm 可运行，lm_head 形状的 FP8 单算子约1.9×；其他小形状有明显波动或回退。探针使用的数值误差和有限值检查不能替代模型任务质量评估。模型量化不保证逐字节或 token ID 相同。

## 双 trace 的证据与限制

`quant-profile-20261018T090919Z` 内分别抓 FP16／FP8，分类产物为 `quant-family-20261018T091049Z`（FP16）、`091045Z`（FP8）。不同序列按内核族归类，不能沿用固定13节点层块。

| 每步内核累计时间 µs | FP16 | FP8 |
|---|---:|---:|
| FP16 GEMM | 4105.60（113个） | 884.71（1个，lm_head） |
| FP8 GEMM | 0 | 1506.25（112个） |
| quantize 分类 | 1.47 | 164.62（112个） |
| attention | 321.59 | 299.65 |
| attention combine | 99.92 | 73.02 |
| 其余 | 295.44 | 190.00 |
| 合计 | 4824.02 | 3118.25 |

“其余”由合计减去表中各项，受舍入影响。分类名是启发式，例如融合 embedding/rms_norm 被旧分类器计入 quantize，不能把分类标签当完整算子语义。

旧版用 FP8 臂的 lm_head 884.71 从 FP16 的4105.60相减，得到3220.89→1506.25（0.468×）。这是跨臂代理估计，已撤回“实测层内精确减半”的说法。在 FP16 自己的 trace 单独归属 lm_head 前，不引用该比值为直接证据。

profiled 内核和下降35.4%，未插桩间隔约下降26%；口径与 profiler 扰动不同，差额尚未归属，不能全部算为图外启动／同步。结果支持权重读取成本重要的解释，不独立证明唯一瓶颈是带宽。

## 上下文扫描

`quant-context-20261018T091413Z`：FP16、batch1/2、输出64，prompt128/2048/8192；max_model_len取最长prompt+64，prefix cache关闭。

| prompt | batch1 ms | batch2 ms |
|---|---:|---:|
| 128 | 4.195 | 4.374 |
| 2048 | 4.976 | 5.856 |
| 8192 | 7.299 | 11.075 |

Qwen3-0.6B 的 FP16 KV 每个上下文 token／序列为114688字节。相对128的增量隐含带宽，按
`(长度−128)×114688×batch / 间隔增量` 计算，四点约282／298／297／276 GB/s（依次2048b1、8192b1、2048b2、8192b2；使用表中舍入值）。这是模型估计，不是硬件计数器的 DRAM 字节测量。

8192相对128的时间增量占总间隔42.5%／60.5%，**不是完整 attention 内核占比**，因为基线也含 attention，其他配置／执行变化也可能影响增量。

独立扫描 `092327Z`、`092557Z`：batch1 的128/2048/8192分别4.126/4.867/6.845与4.185/4.937/7.508 ms；batch2分别4.330/5.666/9.287与4.435/5.769/8.861 ms。8k波动明显，不能把首轮绝对时间或比例当常数。

## 失败、保存与复现

- `quant-context-20261018T091231Z`：第二臂可用KV不足；原始失败保留。最新脚本显式关闭引擎并等内存释放，等待超时或矩阵缺项会失败，不再静默报告passed。
- `quant-profile-20261018T090651Z`：仅一臂且分类器有误；`quant-family-090808Z/090849Z/091023Z`为分类迭代，均被后续成功运行取代。
- 原同秒目录碰撞已由运行入口的随机后缀避免。旧 `--dry-run\r` 参数事故不作为有效复现；最新入口拒绝未知参数。
- 中止的 `quant-decode-20261018T092709Z` 只在WSL，未完成、无真实完成退出码，不作成功证据。
- 清单 `results/sixth-stage-evidence-manifest.json`；原始张量和trace被Git忽略，迁移需单独复制并核对哈希。
- `bash scripts/repro_l4.sh --dry-run`预览；单阶段用 `scripts/run_stage.sh quant-decode`／`quant-context`／`quant-probe`。远程流程见[迁移说明](远程GPU租用与迁移-20261018.md)。

绝对时间、时间比例、FP8收益、min-p收益都需换卡重测。固定模型的权重字节比例是结构事实，执行时间比例不是跨设备常数。lm_head低精度可作为未来候选，需先处理tied embedding、量化误差及任务质量，不承诺固定端到端收益。
