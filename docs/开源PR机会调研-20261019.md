## A：FlashInfer norm 目标架构不匹配时回退（首选，需确认范围）

来源：[issue #5355](https://github.com/flashinfer-ai/flashinfer/issues/5355)，重点看维护者10月6日的后续诊断，不按旧标题修改top-k：原始top-k硬编码归因已被反驳，剩下的是norm的CuTe目标与设备兼容问题。

当前源码固定在 `1279c565fdbb3f3eda61c00ca32e538f996b3c7f`：

- [norm入口](https://github.com/flashinfer-ai/flashinfer/blob/1279c565fdbb3f3eda61c00ca32e538f996b3c7f/flashinfer/norm/__init__.py#L104)：`_use_cuda_norm`依赖架构支持探针。
- [availability](https://github.com/flashinfer-ai/flashinfer/blob/1279c565fdbb3f3eda61c00ca32e538f996b3c7f/flashinfer/cute_dsl/availability.py#L110)：native架构枚举存在就返回True；captured target检查仅用于family fallback分支。辅助函数已移到availability，不要照旧评论从utils寻找。

本轮CPU探针在不安装新DSL的情况下，mock其元数据：设备sm120、captured target sm90a时，原生支持探针仍True，norm的CUDA回退选择仍False。控制组sm120a也True。**这只证明当前判断链不区分该跨major不匹配，尚未证明最新完整内核会实际报错。**

最小贡献范围：只处理norm的编译目标兼容回退及测试，不全局重写JIT，不改top-k编译参数。优先复用库内兼容规则，不能简单要求arch字符串完全相等：普通、`a`、`f`目标的兼容语义不同；也不能影响其它使用availability的算子。

下一实现轮的验收：

1. 隔离新checkout／venv，在单卡新进程设置不兼容CUTE_DSL_ARCH，真实重现旧路径，再验证CUDA回退；不升级当前项目venv。
2. 测正常目标、显式CUDA开关、DSL缺失、unknown/internal API、同major普通兼容及family/architecture-specific情况；覆盖相关rmsnorm／fused／gemma入口，避免修一个入口漏其它入口。
3. 确认正常路径没有新增同步或显著首次调用外开销；保存CUDA graph兼容性和数值对照。无效的目标设置未必能在本卡进入同一代码路径，要据实记录。
4. 讨论区曾有认领／取消认领，侧栏仍可能显示旧分配；公开搜索未发现明确对应修复，**不等于排除所有未索引PR**。实现前重新核对并协调。

为什么优先：已存在具体上游诊断，源码疑点仍在，单卡有条件构造不匹配，能形成有语义的bugfix＋回归测试，范围可控。它属于算子派发兼容修复；已有Triton优化继续作为项目的性能成果。

## B：SGLang 主动暂停不应被scheduler watchdog当作卡死（备选，先协调）

来源：[issue #44835](https://github.com/sgl-project/sglang/issues/44835)。`in_place→abort`死锁已有人接手；其10月18日更新明确把“长in_place暂停被watchdog杀掉”留作不同问题。本轮只将后者作为候选，不抢主死锁修复。

当前源码固定 `834bfe4ef0ec11ac5625fac3f94f60c041a36cb8`，位置：[create_scheduler_watchdog](https://github.com/sgl-project/sglang/blob/834bfe4ef0ec11ac5625fac3f94f60c041a36cb8/python/sglang/srt/managers/scheduler_components/invariant_checker.py#L494)。激活判断看initializing／cur_batch，没有考虑主动pause。

CPU源码探针：空闲False，正常busy=True，paused且保留busy也True。证明接线未屏蔽主动pause，**未实际等待watchdog或运行SGLang服务**。

拟定范围：暂停态的watchdog激活／计时恢复，不修改abort、KV释放或model_update_lock协议。需要测试正常忙碌卡死仍检测、长暂停不被杀、resume不立刻用旧计时误杀、初始化仍被监测，以及soft/hard两种模式。不能全局关闭watchdog，不能只加一个if却漏恢复时间。

实现前先与现接手者确认独立子范围；按当时上游结构追调用者和状态生命周期，并读最新贡献规范。需另外的SGLang隔离环境，当前venv不可替换。
