## 本轮结论（可直接引用）

- **字节模型被干预证实，但只在它覆盖的局部**：fp8 把权重字节减半后，batch 1/2/4 的 decode
  间隔变化 −25.94 / −26.75 / −24.24%（`quant-decode-20261018T090119Z`），而不是预测的 −40%。
  同进程双 trace 分族（`quant-profile-20261018T090919Z` + `quant-family-…091045Z/091049Z`）：
  28 层层内 GEMM **3,220.89 → 1,506.25 µs = 0.468×**（预测 0.5×），`lm_head` 未被 fp8 量化、
  仍 884.71 µs（约 20% 步时），fp8 每步多 112 个激活量化内核约 164.62 µs；内核和 −35.4%，
  未插桩端到端 −26%，差额是图外固定开销。
- **上下文把 attention 项放大**（`quant-context-20261018T091413Z`，fp16，decode 间隔中位 ms）：
  128 → 4.195（b1）/ 4.374（b2）；2048 → 4.976 / 5.856；8192 → 7.299 / 11.075。增量对应的
  KV 读取速率 280–317 GB/s，与权重流同一量级；attention 占比从 7.7% 升到 42.5%（b1）/ 60.5%（b2）。
  这给前几阶段“权重流主导”的结论划了区制边界。
- **fp8 可用性与单算子**：sm_120 上 `torch._scaled_mm` + e4m3 可用，真 tensor core 内核
  `nvjet_sm120_qqhsh_mma_64x64x64_...`；`lm_head` M=1/2/8 1.94/1.93/1.91×（rel_err≈0.038），
  但层内四个 GEMM 在 M=1/2/8 时只有几十微秒，单独计时被启动/时钟噪声主导（0.55–1.91×），
  所以必须到引擎里做配对测量。
- **第二轮复现**（`repro_l4.sh` 连跑两轮，新会话）：fp8 decode −25.71 / −26.56 / −24.99%；
  8k decode b1 6.845–7.508 ms、b2 8.861–9.287 ms（第三轮 092557Z）；min-p 旋钮 decode
  −0.99 / −0.63 / −0.87 / −0.99%（`abba-knob-20261018T091644Z`）。效应方向稳定，绝对值
  跨会话波动 ±15%。
- 结论边界：单卡、单模型、未锁频、128–8192 token 合成 prompt（无真实负载）、KV 两臂都是 fp16、
  fp8 改变数值（token id 只记录不断言）。绝对 ms/GB/s 不可外推；可外推的是比例与机制。
