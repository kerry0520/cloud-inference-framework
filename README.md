# 云端推理框架：小批量 Decode 执行开销

在固定 vLLM 版本上研究小批量生成的输入准备、GPU 执行与结果处理，寻找可验证的专项改进。主线已完成环境、batch1/2/4/8 基线、两组 Decode 时间线、第一层线性投影的真实形状观测，以及 batch2 编译路径的逐层算子归因；小算子副目标已交付可审查补丁，并补齐端到端区间与带宽模型。

**主结果（三个数字）**：batch2 单步内核 3,792 µs，其中 GEMM 占 83.8%、`lm_head` 一项 774 µs（20.4%）且在 CUDA 图外；V151936 batch2 的 min-p 内核局部加速 8.9×（122.9 → 14.0 µs）；整请求 decode 配对差 **−1.10%（95% CI [−1.37, −0.85]，24 轮 ABBA）**。局部 8.9× 只剩 1% 是分母决定的：min-p 只占单步约 1.3%，`(62.5−5.6)/4812 = 1.18%` 与实测区间重合。第二天换引擎会话、把 batch 扩到 8 复跑，batch2 仍为 −1.00% [−1.21, −0.82]，batch8 为 −0.91% [−1.55, −0.75]；节省的绝对量接近常数（两轮平均 62.2 / 55.9 µs，profiler 推得 56.9 µs），百分比随 decode 步变长而稀释。权重流角色的字节-时间关系用留一法单参数模型检验，最大残差 12.8%（含从未参与拟合的 `lm_head`）。完整叙述见[项目叙事（面试版）](docs/项目叙事-面试版.md)，四张图在 `results/figures-20261018T035600Z/`。

副目标交付：`patches/0001-mrv2-min-p-two-stage.patch`（147 行纯增量）把 Triton min-p 两阶段过滤打进 pinned 上游的 `vllm/v1/worker/gpu/sample/min_p.py`，派发窗口为 rows 1–8 且 vocab≥32000。补丁通过 96 组逐字节对照、边界探针、真实 MRV2 logits 4 次一致，真实路径 3,107 次调用全部走新内核（`_min_p_kernel` 0 次）；见[第四阶段记录](docs/第四阶段min-p框架补丁-20261017.md)。

上游形态另有一个更小的版本：`patches/0002-mrv2-min-p-launch-knobs.patch` 只把上游内核的 `BLOCK_SIZE` 改成 16384、加 `num_warps=16`，本机大词表 batch 1–8 拿 3.5–4.2×、32/64/256 不退化，引擎内 decode −0.77%~−0.80%。如果只为上游准备补丁，这个两行版本比 147 行版本更可能被接受；评估见[上游 PR 可行性](docs/上游PR可行性-20261018.md)。

上游同方向工作已经存在：PR [#58907](https://github.com/vllm-project/vllm/pull/58907)（减少逐 tile 的跨 lane 归约）开着三周且无人类 review。我没有另开重复 issue，而是在该 PR 下贴了独立复现与同机三方对比（评论 `6246048928`、`6246069554`）；同机同协议下两行旋钮版比该 PR 更快（fp32 V151936 batch 1：20.3 vs 25.4 µs；batch 32：49.4 vs 54.9），单独加宽 `BLOCK_SIZE` 就解释了几乎全部收益（1024→16384：66.5→15.9 µs）。

**干预检验（第六阶段）**：把权重字节减半（fp16 → fp8 W8A8，同进程、同 prompt、交替测量），batch 1/2/4 的 decode 间隔变化 **−25.9% / −26.8% / −24.2%**，不是单参数模型预测的 −40%。同进程双 trace 分族给出可指认的账：28 层层内 GEMM 由 3,220.9 → 1,506.3 µs（**0.468×**，字节减半确实换成时间减半），但 `lm_head` 没被 fp8 量化、仍是 884.7 µs（约 20% 步时），且 fp8 每步多 112 个激活量化内核（约 164.6 µs）。把 prompt 从 128 拉到 8,192 token，decode 间隔从 4.20 → 7.30 ms（batch 1）、4.37 → 11.08 ms（batch 2），增量对应 280–317 GB/s 的 KV 流——attention 占比从 7.7% 升到 42.5%/60.5%，说明前几阶段的"权重流主导"结论有明确区制边界。见[第六阶段记录](docs/第六阶段量化干预与上下文影响-20261018.md)；换卡复现用 `bash scripts/repro_l4.sh`。
