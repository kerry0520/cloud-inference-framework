# 云端推理框架：小批量 Decode 执行开销

在固定 vLLM 版本上研究小批量生成的输入准备、GPU 执行与结果处理，寻找可验证的专项改进。主线已完成环境、batch1/2/4/8 基线、两组 Decode 时间线、第一层线性投影的真实形状观测，以及 batch2 编译路径的逐层算子归因；小算子副目标已交付可审查补丁，并补齐端到端区间与带宽模型。

**主结果（三个数字）**：batch2 单步内核 3,792 µs，其中 GEMM 占 83.8%、`lm_head` 一项 774 µs（20.4%）且在 CUDA 图外；V151936 batch2 的 min-p 内核局部加速 8.9×（122.9 → 14.0 µs）；整请求 decode 配对差 **−1.10%（95% CI [−1.37, −0.85]，24 轮 ABBA）**。局部 8.9× 只剩 1% 是分母决定的：min-p 只占单步约 1.3%，`(62.5−5.6)/4812 = 1.18%` 与实测区间重合。权重流角色的字节-时间关系用留一法单参数模型检验，最大残差 12.8%（含从未参与拟合的 `lm_head`）。完整叙述见[项目叙事（面试版）](docs/项目叙事-面试版.md)，三张图在 `results/figures-20261017T103530Z/`。

副目标交付：`patches/0001-mrv2-min-p-two-stage.patch`（147 行纯增量）把 Triton min-p 两阶段过滤打进 pinned 上游的 `vllm/v1/worker/gpu/sample/min_p.py`，派发窗口为 rows 1–8 且 vocab≥32000。补丁通过 96 组逐字节对照、边界探针、真实 MRV2 logits 4 次一致，真实路径 3,107 次调用全部走新内核（`_min_p_kernel` 0 次）；见[第四阶段记录](docs/第四阶段min-p框架补丁-20261017.md)。
